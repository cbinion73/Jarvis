# JARVIS Gap Closure Program Contract Index

This index translates the approved Step 3 roadmap into mission-sized Architect contracts. It is a build list, not itself a writable Build assignment. Orchestration must initialize each mission against the committed child contract named for that slice.

## Program invariant

Close coherence before adding breadth:

`conversation -> commitment -> authority -> action -> verification -> memory -> follow-through`

No capability maturity score may increase from task completion alone. QA must observe the acceptance evidence required by the applicable frozen child contract.

## Build order

1. `D0.1` Deployment secret hygiene and configuration proof.
2. `D0.2` Protected API identity boundary.
3. `D0.3` Post-deploy health gate and capability-status contract.
4. `D1` Unified action and verification envelope, delivered through bounded vertical adapters.
5. `D2` Conversation-to-commitment engine.
6. `D3` Versioned workbench artifact envelope, one artifact family per mission.
7. `D4` Attention and interruption governor.
8. `D5` Durable work queue: persistence, shadow scheduling, then gated execution.
9. `D6` Bounded self-research loop.
10. `D7` Integration certification, one provider family per mission.
11. `D8` End-to-end voice proof.
12. `D9` Personal-context packs, one sensitivity class per mission.

`D10` physical and legacy work remains a deferred decision register and is not an active Build mission.

## Contract issuance rule

- Only `D0.1` is frozen and ready for initialization in this commit.
- Later entries remain ordered program scope, not Build authority.
- Architect Office must issue and commit each later child contract before Orchestration initializes it.
- Orchestration may parallelize only when child contracts explicitly declare compatible scopes and dependencies.

## Shared guardrails

- Build works only inside its leased branch, worktree, and owned paths.
- Existing runtime behavior remains unchanged unless the child contract explicitly binds it.
- External credentials, OAuth consent, live devices, production activation, merge, and push remain human-gated.
- Every claimed success requires an entrypoint, state proof, failure proof, and independent QA evidence.
- Chat summaries are notification only; committed contracts, mission state, Git evidence, and test output are authoritative.
